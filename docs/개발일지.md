# ClassZoom 개발 일지

> 라이브 줌 · 마우스 하이라이트 · 드로잉 · 화면 녹화를 한 번에 하는 수업 화면 도구
> 기간: 2026-11-16 ~ 2026-11-17 · 현재 버전 1.3.1 · Windows 10/11, macOS 14 이상

---

## 0. 왜 만들었나

전자칠판으로 수업하다 보면 손이 자주 멈춥니다. 어떤 프로그램은 판서만 되고, 어떤 프로그램은 확대만 되고, 녹화하려면 또 다른 프로그램을 켜야 합니다. 그래서 수업 흐름을 끊지 않고 쓸 수 있는 도구 하나가 필요했습니다.

| 수업 현장의 불편 | ClassZoom이 하는 일 |
|---|---|
| 판서·강조 도구가 메뉴 깊이 숨어 있어 수업 중에 찾기 어렵다 | F7·F8·F9·F10 네 키와 화면 구석의 위젯 하나로 켜고 끈다 |
| 교실 뒤쪽 학생, **저시력 학생**은 화면 글씨가 잘 보이지 않는다 | 라이브 줌 3단계. 단계별 배율(125~800%)을 학생에 맞춰 직접 정한다 |
| 기존 돋보기는 화면 공유·녹화에서 커서가 두 개로 찍힌다 | 확대 화면을 일반 창으로 그려서 공유·녹화에 그대로, 커서 하나만 보인다 |
| 결석생·복습용 강의 영상을 만들려면 녹화 프로그램을 따로 배워야 한다 | F10 한 번으로 마이크·컴퓨터 소리까지 MP4 녹화 |
| 학교 PC는 설치 권한이 막혀 있는 경우가 많다 | 설치 없이 exe 하나로 실행 |
| 집(맥)과 학교(Windows)의 도구가 다르다 | Windows와 macOS에서 같은 단축키·같은 기능 |

## 1. 2026-11-16 (1일 차): 방향 잡기와 라이브 줌

### 결정한 것
- **이름: ClassZoom.** 버전은 1.0.0부터 시작한다.
- 1차 대상은 **Windows**(교실 PC·전자칠판). 개발 도구는 AutoHotkey v2. 가볍고 설치 없이 exe로 배포할 수 있다.
- 확대는 **커서를 따라가고, 그리는 중에는 고정**한다.
- 작업은 main 브랜치에서 하고, 빌드·배포는 GitHub Actions로 자동화한다.

### 만든 것
- **라이브 줌 3단계** (1단계 150% → 2단계 200% → 3단계 300% → 끄기, F7)
  - Windows Magnification API의 확대 컨트롤을 일반 창에 넣었다. 정지 화면이 아니라 영상도 움직이는 그대로 확대된다.
  - Zoom·Google Meet에서 '화면 전체'를 공유하면 확대 화면이 그대로 보인다.
  - Ctrl+휠로 단계를 바꾸고 Esc로 끈다.
- 아이콘을 **돋보기 중심의 컬러 아이콘**으로 새로 그리고 위젯·트레이·설정에 통일했다.
- **처음 실행할 때 뜨는 사용 방법 창**("다음부터 보지 않기" 포함). 단축키는 지금 설정된 값을 읽어 보여 준다.
- 빌드 파이프라인: 문법 검사 → exe 컴파일 → zip → 수동 실행 시 GitHub 릴리스.

### 부딪힌 문제
| 문제 | 원인 | 해결 |
|---|---|---|
| 확대할 때 화면이 흔들린다 (1차) | 매 프레임 배경을 지우고 배율 계산에서 소수점이 들쭉날쭉했다 | 배경 지우기 중단, 가로·세로 같은 배율, 시간 기준 애니메이션 |
| 그래도 흔들린다 (2차) | 커서를 움직일 때마다 화면 전체가 따라 미끄러졌다 | **화면 고정 방식**으로 바꿈: 진짜 커서는 숨기고 그린 커서만 움직이며, 가장자리(15%)에 닿을 때만 화면 이동 |
| 연속으로 F7을 누르면 "확대 2단계" 표시가 남는다 | 감추기 타이머가 밀렸다 | 감출 시각을 기록해 매 프레임 확인 |
| 빌드 서버에서 AutoHotkey 다운로드가 막힌다 | 공식 사이트의 봇 차단 | GitHub 릴리스에서 받도록 변경 |

### 랜딩페이지
- Vercel에 랜딩페이지 게시 (classzoom.songpro.app).
- 쓰임새를 **전자칠판 수업 · 강의 · 화면 녹화**로, 앞세우는 기능을 **라이브 줌 · 마우스 하이라이트 · 드로잉 · 화면 녹화**로 정리했다.
- 문구는 매번 한국어 문체 점검(humanize-korean)을 거친다. 이 규칙을 CLAUDE.md에 적어 두었다.

## 2. 2026-11-17 (2일 차): 녹화, 맥, 배포 다듬기

### 화면 녹화 (1.1 → 1.2)
- **F10** 녹화 시작·정지, **Ctrl+F10** 일시정지, **Ctrl+Shift+F10** 영역을 골라 녹화.
- 3·2·1 카운트다운 뒤 시작하고, 끝나면 `동영상\ClassZoom` 폴더에 MP4로 저장한 뒤 폴더를 연다.
- **마이크(목소리) + 컴퓨터 소리**를 함께 녹음한다. C#으로 만든 작은 도우미가 WASAPI로 소리를 받아 FFmpeg에 넘긴다.
- 카운트다운·녹화 표시창·영역 테두리는 녹화에 찍히지 않게 했다.
- 일시정지할 때마다 조각을 끊고 마지막에 하나로 잇는다.

### macOS판 (1.2.0)
- Swift로 macOS 14 이상용 앱을 만들었다. 네 기능, 위젯, 설정, 사용 방법 창을 모두 넣었다.
- 확대는 ScreenCaptureKit으로 화면을 받아 키우고, 녹화는 AVAssetWriter로 저장한다.
- 서명하지 않은 앱이라 처음 한 번 "그래도 열기"가 필요하다.

### 배포
- 녹화 엔진(FFmpeg·도우미)을 exe 안에 넣어 **exe 하나**로 배포한다. 처음 녹화할 때 한 번만 꺼낸다.
- zip 안의 exe를 바로 실행하면 Windows가 "압축 풀기"를 먼저 묻는다. 그래서 **exe를 따로 받을 수 있게** 릴리스에 올렸다 (1.2.4).
- exe가 134MB로 커져서 엔진을 zip으로 압축해 넣었다. 실행할 때 Windows 기본 tar로 푼다. **134MB → 54.5MB** (1.2.5).
- 프로그램 안에 만든 사람 정보, 저작권, 이용 안내를 넣었다.

### 부딪힌 문제
| 문제 | 원인 | 해결 |
|---|---|---|
| 확대를 한 번도 안 켜고 녹화하면 오류 창 | 아직 없는 확대 창의 핸들을 읽었다 | 확대 창이 있을 때만 순서를 맞춤 (1.2.2) |
| 녹화 일시정지·정지가 안 먹는다 | 위 오류로 상태 확인 타이머가 시작되지 않았다. 명령 파일 쓰기가 겹치면 명령이 사라졌다 | 명령을 쓰고 다시 읽어 확인할 때까지 반복, 조각은 MKV로 저장 (1.2.3) |
| 녹화가 초당 11장, 뒤 창이 깜빡임, 커서 두 개 | GDI 화면 복사가 느리고 겹친 확대 창을 제대로 못 담았다 | **Desktop Duplication(GPU)** 방식으로 바꿈. 안 되는 PC는 예전 방식으로 자동 전환 (1.2.6) |
| 실제 화면에서도 깜빡임·커서 두 개 | 파일 이름이 다른 ClassZoom 두 개가 동시에 떠서 서로의 확대 창을 다시 확대했다 | 시작할 때 다른 ClassZoom을 찾아 끔 (1.2.6) |
| 1.2.2 릴리스 실패 (403) | GitHub 쪽 일시 오류 | 다시 실행해 해결 |

### 성능 (1.2.6)
- 라이브 줌: 화면이 그대로일 때는 초당 30번만 다시 그린다(CPU 약 절반). 커서가 움직일 때만 그린 커서를 옮긴다.
- 확대를 끄고 20초가 지나면 확대 자원을 돌려준다. 기능을 끈 뒤에는 쓰지 않는 메모리를 정리한다.
- 하이라이트는 커서가 멈춰 있으면 창을 옮기지 않는다.

### 드로잉·녹화 기능 추가 (1.2.6)
- **Ctrl+드래그 = 네모**, Shift+드래그 = 원.
- **화살표 끝 잡아 고치기:** 방금 그린 화살표의 머리나 꼬리를 끌면 길이·방향이 바뀐다.
- **움직이는 강조 화살표:** V+드래그. 화살표가 커졌다 작아졌다 하며 시선을 끈다.
- **녹화 화질 선택 창:** 녹화를 시작할 때 1080p(기본)·720p·원본 해상도 중에 고른다. Enter를 누르면 1080p다.
- 랜딩페이지 히어로를 **전자칠판 분수 수업 장면 애니메이션**으로 바꿨다 (짚고 → 쓰고 → 키우고 → 남기고).
