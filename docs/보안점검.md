## 1. 고친 문제

### 1-1. [높음] 내려받기 폴더에 놓인 가짜 `ffmpeg.exe` 실행 (Windows)
- **문제:** exe 옆에 `ffmpeg.exe`와 `classzoom-rec.exe`가 있으면 그것을 먼저 쓰게 되어 있었다. 사용자는 ClassZoom을 '내려받기' 폴더에서 바로 실행하는 일이 많다. 그 폴더에 같은 이름의 다른 프로그램이 받아져 있으면 녹화 버튼을 누를 때 그 프로그램이 실행된다(바이너리 바꿔치기).
- **조치:** exe로 실행할 때는 exe 옆의 파일을 **쓰지 않는다.** 녹화 엔진은 exe 안에 든 것만 꺼내 쓴다. 소스(.ahk)로 실행할 때만 옆 파일을 쓴다.
- FFmpeg을 바꿔 쓰는 방법(LGPL)은 `%LOCALAPPDATA%\ClassZoom\engine\<버전>\ffmpeg.exe`를 교체하는 것으로 바꾸고, 라이선스 안내문도 함께 고쳤다.

### 1-2. [중간] 업데이트 주소 검증 강화 (Windows·맥)
- **문제:** version.txt의 다운로드 주소는 "이 저장소 주소로 시작하는가"만 확인했다.
- **조치:** 이 저장소의 GitHub 주소이면서 URL에 쓰는 글자만 들어 있고 `..`가 없을 때만 연다. 아니면 최신 릴리스 페이지를 연다.
- 버전 파일은 HTTPS로만 받고, 받는 쪽에서 실행하는 것은 없다(브라우저로 페이지를 열 뿐).

### 1-3. [중간] 빌드 토큰 권한 축소 (GitHub Actions)
- **문제:** 모든 빌드 작업이 저장소 쓰기 권한(contents: write)을 가졌다.
- **조치:** 기본은 읽기 권한만 두고, 릴리스를 만드는 작업에만 쓰기 권한을 준다(최소 권한).

### 1-4. [보완] 녹화 저장 위치 표시 (Windows)
- 설정 파일(settings.ini)이 exe 옆에 있어서, 누가 이 파일을 바꿔 두면 녹화가 낯선 폴더나 네트워크 폴더로 저장될 수 있다.
- 녹화 화질 선택 창에 **저장 위치**를 함께 보여 줘서 사용자가 눈으로 확인하게 했다.

## 2. 문제없음 확인

| 항목 | 확인 내용 |
|---|---|
| 개인정보 | 개인정보 수집·전송 없음. 녹화 파일은 사용자 PC에만 저장 |
| 네트워크 | 설정 창을 열 때 version.txt 1개만 HTTPS로 읽음 (맥은 캐시 없는 임시 세션) |
| 명령 실행 | 외부 프로그램은 전체 경로로 실행 (tar.exe는 `C:\Windows\System32`, 녹화 엔진은 사용자 폴더). 셸을 거치지 않아 명령 끼워 넣기가 되지 않음 |
| 녹화 도우미 | 제어·상태 파일은 사용자 전용 임시 폴더. 알 수 없는 명령은 무시하고 직전 명령 유지. 조각 목록 파일은 작은따옴표를 이스케이프 |
| 설정값 | 숫자는 범위로 자르고, 단축키는 Ctrl·Alt·기능키 규칙으로 검사 |
| 중복 실행 | 다른 ClassZoom만 골라 끔 (이름이 classzoom으로 시작하고 AutoHotkey 창이 있는 프로세스) |
| 화면 캡처 제외 | 녹화 표시창·카운트다운·화질 창은 녹화에 찍히지 않음 |
| 맥 권한 | 화면 기록·마이크는 처음 쓸 때 시스템이 묻는다. 키 상태 읽기는 권한이 필요 없는 방식(CGEventSource)을 씀. 전역 키 감시(손쉬운 사용 권한)는 쓰지 않음 |
| 랜딩페이지 | CSP(스크립트는 자기 도메인만), frame-ancestors 'none', nosniff, Referrer-Policy, 카메라·마이크·위치 차단. 다운로드 링크는 `https://github.com/`으로 시작할 때만 바꿔 넣고, 글자는 textContent로만 넣음 |
| 라이선스 | 앱은 MIT, FFmpeg은 LGPL 2.1 전문과 출처를 함께 배포 |

## 3. 남은 위험과 권고

| 위험 | 영향 | 권고 |
|---|---|---|
| 코드 서명이 없음 (Windows·맥) | 처음 실행할 때 경고가 뜨고, 받은 파일이 원본인지 사용자가 확인하기 어렵다 | Windows 코드 서명 인증서, Apple Developer ID 서명·공증. 그 전까지는 릴리스 노트의 SHA-256으로 확인하도록 안내 |
| 빌드 도구를 해시 확인 없이 받음 | AutoHotkey·FFmpeg 배포처가 공격받으면 빌드에 섞일 수 있다 | 버전을 고정하고 SHA-256을 확인하는 단계 추가 |
| GitHub 액션을 태그(@v4)로 참조 | 액션 저장소가 바뀌면 빌드에 영향 | 커밋 해시로 고정 |
| 설정 파일이 exe 옆에 있음 | 같은 폴더에 쓸 수 있는 사람이 설정을 바꿀 수 있다 | 저장 위치는 화면에 보여 주도록 보완함. 필요하면 설정을 `%APPDATA%`로 옮기는 방안 검토 |

같은 사용자 계정으로 이미 실행 중인 악성 프로그램은 막을 수 없다. 이는 데스크톱 앱 공통의 한계라 범위에서 뺐다.
